# Skill: Check VCD Format Compliance

## Goal
Verify whether a Value Change Dump (VCD) file generated by a Verilog simulation complies with the IEEE VCD specification and common simulator requirements (e.g., Synopsys VCS, Verilator, Icarus Verilog).

This skill helps detect structural and syntax issues in VCD files before they are used for waveform visualization, coverage analysis, or post-processing scripts.

---

## When to Use

Use this skill when:

- A VCD file cannot be opened by waveform tools (GTKWave, Verdi, etc.)
- Python scripts fail when parsing VCD
- VCS/Verilator generated VCD appears corrupted
- A pipeline requires validating simulation output files
- You need to ensure a VCD file follows IEEE dump format rules

---

## Expected Input

Input should include:

- Path to the `.vcd` file
- Optional: simulator used (VCS / Verilator / Icarus)

Example:


check_vcd_format simulation.vcd


---

## Validation Checklist

The following sections must be validated.

### 1. Header Section

Ensure the file begins with valid header keywords.

Required structure:


$date
...
$end

$version
...
$end

$timescale
<number><unit>
$end


Valid units:


s
ms
us
ns
ps
fs


Example:


$timescale 1ns $end


---

### 2. Scope Declaration

Scopes must be properly nested.

Example:


$scope module tb_top $end
$scope module dut $end
...
$upscope $end
$upscope $end


Rules:

- `$scope` must match `$upscope`
- nesting must be balanced

---

### 3. Variable Definitions

Signal declarations must follow:


$var <type> <width> <symbol> <reference> $end


Example:


$var wire 1 ! clk $end
$var wire 8 " data[7:0] $end


Check:

- type valid (`wire`, `reg`, `integer`, etc.)
- width > 0
- symbol unique

---

### 4. End of Definitions

Ensure the definitions terminate with:


$enddefinitions $end


Everything after this should be value changes.

---

### 5. Time Format

Time changes must follow:


#<time>


Example:


#0
#10
#20


Rules:

- must be integer
- must be non-decreasing

---

### 6. Value Change Format

Two formats allowed.

#### Scalar


0!
1!
x!
z!


Format:


<value><symbol>


---

#### Vector


b10101010 "


Format:


b<binary> <symbol>


---

### 7. Symbol Consistency

Every symbol used in value changes must appear in a `$var` definition.

Example:


$var wire 1 ! clk $end


Then later:


1!
0!


Valid.

---

### 8. Illegal Tokens

Detect invalid constructs:

Examples:


$var wire clk
#time
b10201 !


Errors:

- missing `$end`
- invalid binary digits
- malformed declarations

---

## Python Validation Strategy

Recommended parsing steps:

1. Read file line-by-line
2. Parse header
3. Build symbol table from `$var`
4. Detect `$enddefinitions`
5. Validate time/value sections
6. Check symbol references

Pseudo workflow:


parse_header()
parse_scope()
parse_variables()
check_enddefinitions()
parse_value_changes()
validate_symbols()


---

## Common Errors

| Error                          | Cause                             |
| ------------------------------ | --------------------------------- |
| Missing `$enddefinitions`      | Simulation terminated incorrectly |
| Unknown symbol in value change | Corrupted VCD                     |
| Non-monotonic time             | Simulation dump error             |
| Missing `$upscope`             | Scope nesting issue               |
| Invalid vector format          | Dumping bug                       |

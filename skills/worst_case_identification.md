# Skill: 最坏数据情况识别

## 目标

识别 VCD 波形数据中信号跳变活动最频繁的时间段（最坏情况），用于功耗分析、时序分析、压力测试等场景。

本技能帮助识别：
- 信号跳变次数最多的时间窗口
- 可能导致高功耗、高噪音的时间段
- 需要重点进行验证的关键时段

---

## 何时使用

使用本技能的场景：
- 需要分析芯片最高功耗时段
- 寻找可能的时序违规窗口
- 识别仿真中最复杂的场景
- 进行性能瓶颈分析
- 生成压力测试向量

示例请求：
```
识别最坏情况窗口
分析跳变次数最多的时段
```

## 输入要求

### 必需输入
- CSV 格式的跳变次数统计文件（来自任务2的输出）

### 可选输入
- 跳变阈值百分比（默认 70%）
- 最小窗口数量要求

示例输入：
```
跳变统计文件: toggle_counts_5cycles.csv
阈值: 70%
```

---

## 最坏情况定义

### 标准定义
1. **全局最坏窗口**：跳变次数最多的窗口
2. **次坏窗口**：跳变次数达到全局最大值 70% 以上的窗口

### 阈值说明
- **默认阈值**：70%
- **调整依据**：根据具体应用场景可调整为 60% - 90%
  - 70% 适用于一般功耗分析
  - 85% 适用于严格的时序检查
  - 60% 适用于寻找多个候选窗口

---

## 识别算法

### 步骤1: 读取统计数据
从 CSV 文件读取所有窗口的跳变次数。

### 步骤2: 计算全局最大值
```
max_toggles = 所有窗口中的最大跳变次数
```

### 步骤3: 计算阈值
```
threshold = max_toggles * threshold_percentage
```

示例：
```
max_toggles = 100
threshold_percentage = 0.7
threshold = 70
```

### 步骤4: 筛选最坏情况窗口
```
worst_windows = []
for window in all_windows:
    if window.toggle_count >= threshold:
        worst_windows.append(window)
```

### 步骤5: 排序（可选）
按跳变次数降序排列最坏情况窗口。

## 实现要点

### 1. 窗口连续性检查
识别连续的最坏情况窗口，可能表示一个较长的高活动期。

```
连续窗口示例:
  窗口 #2 (30-229ns) - 9次跳变
  窗口 #3 (50-249ns) - 9次跳变
  窗口 #4 (70-269ns) - 9次跳变
  → 合并为 30-269ns 的高活动期
```

### 2. 多窗口大小分析
同时分析不同窗口大小的统计：
- 5周期窗口：捕捉短时高活动
- 10周期窗口：识别较长的活跃期

### 3. 信号细分分析
除了统计所有信号的总跳变，还可以：
- 分析每个信号的跳变贡献
- 识别主导高活动的关键信号

## 常见问题

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 没有最坏情况窗口 | 所有窗口跳变均匀 | 降低阈值百分比 |
| 太多最坏情况窗口 | 阈值设置过低 | 提高阈值百分比 |
| 最大跳变次数异常 | 单个窗口数据问题 | 检查原始数据 |
